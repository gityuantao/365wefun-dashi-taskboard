# 部署记录

## 2026-08-10 iOS 全 App TestFlight 闸门脚本

`scripts/stage-all-ios-apps.mjs` 是编排器的单 App stage/readback 命令。编排器按 `.data/orchestration.json` 中启用的 `iosApps` 顺序分别调用，两个 App 的权威配置为：

- `E365AU` / `online.365english.app` / Internal Testing 组 `团队内测`
- `E365CN` / `online.365english.china` / Internal Testing 组 `Internal Testing`

本地命令配置为：

```json
{
  "iosTestFlightStageCommand": ["/Users/yuantao/.local/bin/node", "scripts/stage-all-ios-apps.mjs", "stage"],
  "iosTestFlightReadbackCommand": ["/Users/yuantao/.local/bin/node", "scripts/stage-all-ios-apps.mjs", "readback"],
  "iosTestFlightTimeoutMs": 1800000
}
```

`.data/` 只是本机运行配置，不提交。命令的工作目录必须是 taskboard 仓库根，`STAGING_REPO_PATH` 必须指向产品仓库 `365wefun`，其 iOS XcodeGen spec 为 `apps/ios/project.yml`。

### 私密环境变量

真实 stage/readback 由运行编排器的私密 shell/launchd 环境提供以下变量，不得写入源码仓库、`.data/orchestration.json` 或日志：

- `ASC_KEY_ID`：App Store Connect API Key ID。
- `ASC_ISSUER_ID`：App Store Connect Issuer ID。
- `ASC_PRIVATE_KEY_PATH`：绝对路径，文件名必须严格为 `AuthKey_<ASC_KEY_ID>.p8`，权限不得对 group/other 开放（建议 `600`）。

脚本会为 REST 回读在内存中临时签发 ES256 JWT；altool 通过 `API_PRIVATE_KEYS_DIR` 找到同一 `.p8` 文件。命令展示层会将 `--api-key` 和 `--api-issuer` 的值替换为 `[REDACTED]`，不打印私钥路径、JWT 或 App Store Connect 原始响应正文。

### Stage 路径

1. 验证 App 身份、完整 Candidate commit、精确测试组名与私密 Apple 配置。
2. 在系统临时目录创建该 commit 的 detached Candidate worktree；已存在的 Candidate 目录会直接拒绝，不覆盖。
3. 运行 XcodeGen，用 App Store Connect 该 App 全部历史整数 build number 的最大值加一生成新 build number。
4. 针对当前 scheme 运行 Xcode build-settings preflight 和 tests。配置必须是 release-optimized `Staging`，API 必须严格为 `https://test-api.365english.online`，不得含 `DEBUG` 编译条件。
5. 使用每 App 独立的 DerivedData/archive/export/IPA 解包路径完成 archive 和 App Store Connect export。
6. 分别读取 archive 和 IPA 内 App `Info.plist`，严格匹配 bundle ID、marketing version、build number 和 Staging API；扫描 App 二进制不得编译进 `E365_UI_TEST_IAP_MODE`、`QuickLessonUITestIAPAPI` 或 `E365ForceChinaStore`，App bundle 也不得包含 `.storekit` 配置。
7. 使用 altool API-key 模式上传精确 IPA，输出一行 JSON stage evidence。
8. 无论测试、archive、export 或 upload 成功失败，都通过 `git worktree remove --force <exact-candidate-path>` 清理本次 Candidate，再删除本次独占临时目录。

### Readback 路径

readback 只查询当前 bundle/version/build 精确三元组。App Store Connect `processingState` 必须为 `VALID`；`FAILED`/`INVALID` 立即失败。处理成功后，脚本只选择该 App 下名称精确匹配且 `isInternalGroup=true` 的唯一 beta group，建立 build relationship，然后持续回读 group builds，直到确认成员关系。上传命令的退出码不能代替这一权威回读。

任一 XcodeGen、tests、archive、export、upload、processing 或 group-membership 步骤失败，命令均非零退出；本脚本不提交 App Review 或生产发布。

### 无凭据 dry-run

dry-run 不创建 worktree、不运行 Xcode、不读 Apple 凭据、不访问 App Store Connect，也不上传。它只校验公开输入并打印 stage 的脱敏命令计划及最后一行 JSON evidence。readback dry-run 必定非零退出，禁止合成 processing/group 成功证据，因此即使编排器误带 `IOS_STAGING_DRY_RUN=1` 也不能让闸门通过。

```bash
IOS_STAGING_DRY_RUN=1 \
IOS_APP_ID=au \
IOS_SCHEME=E365AU \
IOS_BUNDLE_ID=online.365english.app \
IOS_MARKETING_VERSION=1.0.3 \
IOS_TESTFLIGHT_GROUP='团队内测' \
STAGING_CANDIDATE_COMMIT=<40-character-candidate-commit> \
STAGING_REPO_PATH=<absolute-path-to-365wefun> \
IOS_STAGING_DRY_RUN_BUILD_NUMBER=2046 \
node scripts/stage-all-ios-apps.mjs stage
```

Task 6 只实现并 dry-run 验证这条路径，未执行真实 archive/upload/readback。首次受控真实上传与两 App 的端到端证据属于 Task 7。
