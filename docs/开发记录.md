# 开发记录

## 2026-08-10：ClickUp 评论图片作为 AI 输入

分析、开发和验收作业现在会读取 ClickUp 最近评论中的图片附件，并以 Codex 的真实图片输入传入。只有图片、没有文字的评论同样会被保留；提示词通过「评论 `<commentId>` 图片：`<filename>`」保持图片与评论的对应关系。

### 支持范围与默认限制

- 只接受 PNG、JPEG、WebP 和 GIF；同时校验响应 MIME 类型和文件签名，HTML 错误页或者类型与字节不匹配时拒绝处理。
- 每次作业选择最近 12 条评论，最多读取 8 张图片，单图上限 10,000,000 字节，总量上限 30,000,000 字节。
- 超出图片数量、单图或总量限制时，优先保留最新反馈，并在上下文中标记具体评论、文件名和 `IMAGE_LIMIT`，不会静默丢弃。

### 失败关闭与排查

选中的图片缺少可用 URL、下载或鉴权失败、内容损坏、类型不支持或 MIME 不匹配时，当前 AI 作业会失败关闭，不会忽略图片继续执行。分析作业转人工补充，开发和验收作业转待补充信息。

运营人员从 ClickUp 评论或作业错误中查看统一诊断：

```text
comment image unavailable: <filename> (<code>)
```

`<filename>` 直接定位无法读取的附件，`<code>` 区分 `IMAGE_UNAVAILABLE`、`INVALID_IMAGE`、`IMAGE_TYPE_MISMATCH`、`ATTACHMENT_HOST`、`HTTP_401` 等原因。诊断不包含 ClickUp token、带签名的附件 URL 或本地临时路径；重新上传该文件后，按 ClickUp 评论中的状态提示重新启动对应阶段。

### 临时文件清理

图片只写入操作系统临时目录下的 `taskboard-clickup-images-*` 任务专用目录：目录权限为 `0700`，文件权限为 `0600`，上游文件名不用作本地路径。Codex 返回、抛错、超时或取消时均通过同一 `finally` 路径删除整个目录；收集中途失败也会先清理已下载图片再返回错误。这些图片不写入 Git、数据库或长期日志。
